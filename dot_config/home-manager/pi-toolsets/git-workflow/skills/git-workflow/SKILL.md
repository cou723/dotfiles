# Git workflow（たたき台）

このスキルは LLM が判断するための指針であり、自動コミット Hook ではない。
方針の出所を以下で区別する。「ユーザーの明示方針」を、補足案によって狭めたり、
補足案をユーザー自身の発言として扱ったりしない。実際の操作は今回の許可範囲で行う。

## 1. ユーザーの明示方針

以下はユーザーが自分の言葉で指定した好み。

- グローバルな Git スキルとして、個人の好みに合わせる。ただし外部・仕事・共同開発の
  リポジトリでは、そちらのプロジェクトのルールを優先する。
- 個人運用のコミットメッセージは基本的に日本語にする。
- コミットはなるべく細かく、怖がらず積極的に作る。
- コミットを変更の要約だけでなく、Why や調査履歴を含むプロジェクトの履歴として機能させる。
- 履歴として成り立つよう、コミット列を分かりやすく整えることを心がける。
- 各コミットが単独で動作することや CI が通ることは必須ではない。
  それよりプロジェクトの履歴として意味があることを優先する。
- 曖昧な判断は LLM ベースで扱うことを想定する。
- コミットの一連の実作業はなるべく subagent に任せ、親に詳細な作業コンテキストを持たせない。
- スキル内でも、ユーザーが明示した内容とアシスタントが補った内容を分けて記述する。

## 2. 選択肢への回答で確認された運用境界

以下はアシスタントの選択肢に対し、ユーザーが選択した方針。

- 規約や履歴などの根拠を調べ、運用方針を判断できない場合は確認する。
- コミットは依頼・許可されたときに行う。実装依頼だけをコミットの許可とみなさない。

コミットを任された作業では、許可された範囲内で意味のある区切りごとに積極的に作る。
一件ごとの承認を必須にする意図ではない。今回の指示で境界が変わった場合はそれに従う。


## 3. アシスタントによる補足案：親の委譲手順

以下は明示方針を具体化する運用案。fresh context、同じ作業ツリー、直列実行、
返却形式などはアシスタントの補足であり、ユーザーの直接の発言ではない。

### 役割の分岐

- 親エージェント：このファイルを読み、許可と対象を整理して git-committer に委譲する。
  規約調査、全差分の精査、分割案、メッセージ作成、実行手順は子に任せる。
- git-committer またはこの役割を明示された子：このファイルと
  [子向け作業手順](references/commit-worker.md)を読み、自分で完結する。再委譲しない。
- 子が技術的に起動できない場合：失敗を報告し、親による代行や別 CLI への切り替えを
  無断で行わない。明示的に親へ直接作業を依頼された場合は、同じ子向け手順に従う。

Skill の読み込みはコミット実行の許可ではない。読み取り・分割提案だけの依頼でも
委譲できるが、その場合は子に Git 状態の変更を許可しない。

### 引き渡す情報

親は会話全文ではなく、以下の短い brief を渡す。差分から Why を捏造させない。

- 目的と背景：なぜ変更したか、重要な制約、採用・不採用の判断。
- 調査事実：実際に確認したことと推測の区別。長い資料は非秘匿の参照先で渡す。
- 対象：作業ツリーの絶対パス、期待するブランチと開始 HEAD、
  対象ファイル・hunk、除外する既存変更やステージ済み変更。
- 検証：実施した確認と結果、未実施事項。
- 権限：提案のみかコミット実行か。push・履歴書き換え等は別途明記。
- 引き渡し：同じ作業ツリーで他の writer が動いていないこと。

最低限のブランチ・HEAD・status は引き渡し用に確認するが、親が全差分の調査を重複して行わない。
対象や背景が不明なら、子に不明点として渡すか必要な確認を行う。

### 起動と排他

一つの作業区切りに一つの子を使い、必要なら複数コミットを作らせる。一コミットごとに
子を作らない。既存変更を扱うので同じ作業ツリーを指定し、worktree 分離を明示的に無効にする。
fresh context を明示し、親の会話全文を引き継がない。

起動の形（実際の task と cwd を置き換える）：

```json
{
  "agent": "git-committer",
  "task": "目的・調査事実・対象と除外・検証結果・権限・期待ブランチとHEAD・排他確認を記載",
  "cwd": "/absolute/path/to/current/worktree",
  "worktree": false,
  "async": true,
  "options": { "context": "fresh" }
}
```

親も他の子も、引き渡しから終了まで同じ作業ツリー・index・HEAD への書き込みを止める。
別 worktree でも共通ブランチや ref への競合操作は避ける。これは調整の規約であり OS ロックではない。
非同期完了の通知を受けて再開する。sleep や status のポーリングをしない。
子が質問・失敗・部分完了を返した場合は解決するまで writer を重ねない。
途中停止後は実際の HEAD・index・差分を確認し、重複コミットになる再実行を避ける。

### 親が受け取る結果

通常は結果、作成コミットの hash と件名、残差分、検証結果、注意点だけを受け取る。
子の生ログや試行錯誤を親のコンテキストへコピーしない。判断に必要な質問・失敗・規約の
衝突・権限不足は省略しない。結果を短くするために未検証を成功へ言い換えない。

この実行には pi-subagents とモデル認証が必要。Skill 単体の発見は Agent の登録や
実行基盤の利用可能性を保証しない。
