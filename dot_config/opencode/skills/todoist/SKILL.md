# todoist

`todoist` MCP サーバー（公式リモート MCP）を用いて、ユーザーの Todoist アカウントを操作するスキルです。

## 反応する状況

- タスク（ToDo）の追加・更新・完了・削除
- タスクの検索（日付・キーワード・プロジェクト・セクションなど）
- プロジェクトやセクションの管理
- コメントの管理、担当者（アサイン）の変更
- 最近のアクティビティ確認

## 認証

初回は OAuth 認証が必要です。ツール呼び出しが認証エラーで失敗したら、`opencode mcp auth todoist` を実行してブラウザで完了してください。

## 活用方法

1. 必要に応じて `get-overview` でアカウントの概要（プロジェクト、今日のタスク等）を取得する
2. 目的に合ったツールを呼び出す
3. 結果を確認し、ユーザーへ報告する

## タスク追加の既定動作

ユーザーが保存先を明示せず「タスクを追加して」などと依頼した場合は、次を既定とします。

- `gc_GoogleCalendar` プロジェクト（ID: `6Hgcj6gJrPJFvXGp`）へ追加する
- 追加前に `fetch-object` で同プロジェクトを取得し、最新の説明欄にある運用ルールを確認する
- プロジェクト説明を優先度、ラベル、日付、階層化に関する唯一の正本として扱う
- この Skill にプロジェクト説明の本文を複製しない。説明と矛盾する古い知識や推測を使わない
- 依頼内容だけではルールに沿った登録内容を一意に決められない場合は、必要最小限の確認をする
- ユーザーが別の保存先や運用方法を明示した場合は、その指定を優先する

## `task` の粒度

`task` ラベルを付ける項目は、原則として集中して約1時間で完了できる具体的なアクションにします。

- 1つの成果または完了条件だけを持たせる
- タイトルは動詞から始め、完了したかを客観的に判断できる表現にする
- 調査、実装、確認など性質の異なる作業を一項目へ詰め込まない
- 1時間を明らかに超える見込みなら、独立して完了できる約30〜60分のサブタスクへ分割する
- 分割後の複数タスクが共通の成果を目指す場合は、親を `goal`、子を `task` とする
- 分割できない作業や、分割により管理コストが便益を上回る作業は例外として長い `task` を許容する。その場合は説明欄に想定所要時間と完了条件を記載する
- 所要時間や分割方法を判断できない場合は、勝手に細分化せずユーザーへ確認する

タスク追加時は、プロジェクト説明のルールを確認したうえで、依頼された作業がこの粒度を満たすか判定してから登録します。

## 主なツール

| 目的 | ツール |
| --- | --- |
| アカウント概要の取得 | `get-overview` |
| タスク追加 | `add-tasks` |
| タスク更新 | `update-tasks` |
| タスク完了 | `complete-tasks` |
| タスク検索 | `find-tasks` / `search` |
| 日付によるタスク取得 | `find-tasks-by-date` |
| 完了済みタスク取得 | `find-completed-tasks` |
| プロジェクト管理 | `add-projects` / `find-projects` / `update-projects` |
| セクション管理 | `add-sections` / `find-sections` / `update-sections` |
| コメント管理 | `add-comments` / `find-comments` / `update-comments` |
| 担当者変更 | `manage-assignments` |
| アクティビティ取得 | `find-activity` |
| ユーザー情報取得 | `user-info` |
| オブジェクト取得・削除 | `fetch-object` / `delete-object` |

## 注意事項

- フィールドのクリアはツールスキーマに記載された特殊値（例: `unassign`）で行う
- `delete-object` は破壊的操作なので、実行前に必ずユーザーへ確認する
