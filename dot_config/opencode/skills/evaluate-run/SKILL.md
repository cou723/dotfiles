# evaluate-run

過去の issue-loop 実行を調査し、期待ワークフローどおり動作したかを評価するスキルです。

## 引数（任意）

`$ARGUMENTS` で対象を指定できる。未指定なら cwd のプロジェクトの「直近の issue-loop セッション」をアンカーにする。
- パス（リポジトリ）… そのプロジェクトを対象にする
- セッション ID … そのセッションをアンカーにする
- `latest` … cwd プロジェクトの最新 issue-loop セッション（デフォルト）

## 評価手順

### 1. 対象セッションの特定
issue-loop-plugin によるセッションを特定します。`promptSource` が `issue-loop-plugin` であるセッションが対象です。

### 2. ワークフローの復元
セッションログから以下の情報を抽出します:
- issue の内容と要求事項
- 計画モードで作成された実行計画
- ビルドモードでの実行内容
- 各ステップでのツール使用状況

### 3. 成否の判定
以下の観点で成功・失敗を判定します:
- issue の要求事項が満たされているか
- 計画通りに実行が進んだか
- エラーや中断が発生していないか
- 最終結果が期待通りか

### 4. 問題点の抽出
失敗箇所や改善点を抽出し、以下のカテゴリで分類します:
- 計画の不備
- 実行時のエラー
- コンテキスト不足
- モデルの誤解釈

## 出力形式

1. **実行概要**: issue と期待成果物
2. **ワークフロー履歴**: 各ステップの実行結果（✅完了 / ❌失敗 / ⚠️警告）
3. **成功・失敗の判定**: 明確な合格・不合格判定
4. **改善提案**: 問題点と具体的な改善方法
