# コミット確認フック（このリポジトリ限定の試験運用）

Pi のプロジェクト拡張 `extensions/commit-reminder.ts` を使う。
Claude Code や外部 Hooks ランナーは不要。Nix 管理の Pi 本体は変更しない。
`.chezmoiignore` でホームへの配置を除外し、別のプロジェクトでは動かさない。

## 有効化・停止

このリポジトリで Pi を起動し、プロジェクト設定の読み込みを許可する。
既存セッションでは `/reload`（または再起動）する。
停止するときは `.pi/extensions/commit-reminder.ts` を拡張ディレクトリの外へ移動し、再読み込みする。

## 動作

- 読み込み時の差分を基準にし、既存の未コミット変更だけでは通知しない。
- 1依頼（`before_agent_start` から始まる入力の処理）につき、通知は最大1回。
  追加のモデル実行で発生する `agent_start` では回数をリセットしない。
- `turn_end` で差分が変わった場合、コミット確認をカスタムメッセージとして追加する。
  作業中は強制再実行せず、次の自然なモデル実行に渡す。
  通知後は、追加編集・ステージ操作・コミットがあっても、その依頼では再通知しない。
- 途中で通知済みなら、`agent_before_settle` でも再通知・追加実行しない。
  終了直前に初めて差分の変化を検出した場合だけ通知し、Pi が続行可能な場合に限って確認用の実行を1回要求する。
- 抑制中も差分の基準は更新する。次の依頼でも同じ差分だけでは再通知しない。
  ユーザーの中断やエラーでは通知・実行再開をしない。
- 文面は区切りのよい時点でのコミットを促す。権限拒否などの場合は一度報告すればよく、同じ依頼内の再試行は不要と伝える。
  拒否の自動判定は行わず、通知回数の制限によって追加の催促を防ぐ。
- 時間ベースの再通知は行わない。長い依頼でも最大1回とし、必要なら利用状況を見て調整する。
- 差分にはステージ済み・未ステージ・未追跡ファイルを含み、内容の識別値だけを保持する。
  `.gitignore` 対象は含めず、ファイル内容をプロンプトに載せない。
- Git確認に失敗したらUIに警告し、自動処理を続けない。

フック自身はコミット・ステージ・pushを行わない。変更の所有者も判定しない。
AIには自分の作業分だけをコミットするよう指示する。コミットの保証や、同時編集に対する隔離ではない。
強制終了時には動作しない。差分が大きすぎる場合も確認に失敗するため、手動確認が必要。
追加のモデル実行には通常の利用料金がかかる。

## 検査

インストール済み Pi の `lib/pi` を指定する（以下は導入時のパス）。

```sh
PI_PACKAGE_DIR=/nix/store/fylxrmnhiffb7f18lmwmwr013r9a1nqy-pi-1.1.0/lib/pi \
  node --test .pi/tests/commit-reminder.test.mjs
```

一時Gitリポジトリで差分検出とイベント処理を検査し、実際のPiローダーでも拡張を読み込む。
通知後の追加編集、終了時の重複抑制、次の依頼でのリセット、終了時だけ検出した変更の続行、続行不可・中断・エラーも検査する。
実モデルが適切にコミットするかどうかは、試験運用中に確認する。
